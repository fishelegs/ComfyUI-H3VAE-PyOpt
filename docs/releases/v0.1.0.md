# ComfyUI-H3VAE-PyOpt v0.1.0

Initial public release of the optimized PyTorch/Triton MiniMax H3 video VAE
runtime for ComfyUI.

## Highlights

- Drop-in ComfyUI VAE loader integration for existing `VAE Encode` and
  `VAE Decode` workflows.
- PyTorch/Triton acceleration without requiring a prebuilt TensorRT engine for
  the PyOpt runtime.
- Decoder optimizations including QK RMSNorm/RoPE fusion, whole-decoder
  `torch.compile`, and batched spatial tiles.
- Encoder optimizations including fused normalization/activation/padding
  kernels, channels-last-3d execution, staged clip batching, and whole-graph
  compilation.
- Benchmark and quality-comparison scripts for reproducible engineering
  evaluation.
- MIT licensing for source code authored for this repository.

## Installation prerequisites

A supported NVIDIA CUDA environment with a compatible PyTorch and Triton
installation is required. The runtime also needs MiniMax H3 / FL2VA VAE model
code and matching model weights supplied separately by the user.

The repository does not contain MiniMax H3 model code, model weights, or
TensorRT engines. Those assets retain their applicable third-party licenses.

## Performance scope

The README contains the current measured benchmark results, including
comparisons against stock ComfyUI and TensorRT paths. Those results are tied to
specific GPU, PyTorch, CUDA, tile, input-shape, and benchmark configurations.
They are engineering measurements, not universal performance guarantees.

When comparing results on another system, record at least GPU model, VRAM,
operating system, Python version, PyTorch version, CUDA version, Triton version,
input resolution and frame count, tile configuration, encode latency, decode
latency, and relevant correctness/quality measurements.

## Known limitations

- Current performance validation is primarily Linux/NVIDIA CUDA focused.
- Windows requires a Triton build compatible with the user's Python, PyTorch,
  and CUDA environment.
- MiniMax H3 / FL2VA model code currently needs to be supplied separately.
- Changing tile sizes may change numerical output and requires quality
  re-validation.
- The optional `fast_linear` path is an explicit speed/accuracy trade-off and
  is disabled by default.
