# Norm1 R1024 / two-warp follow-up — 2026-10-08

**The local fusion is exact and faster, but this round is not adopted.**
The previously unsupported R1024 / two-warp schedule now passes independent
local checks and all 35 decoder-layer shadows. Its local chain is **7.07%
faster**. The complete video comparison between independently compiled
ordinary modules fails the predeclared RGB screen, so no full-decoder timing
runs. Published records remain INT8 encode **8.458108 s**, INT8 decode
**6.508537 s** and fused FP16 decode **10.923379 s**.

This follows the [W8/W16 numerical-contract experiments](decoder_norm1_contract_2026-10-03.md).
The research helper is not imported by the runtime, and no Loader option is
added. Current precision defaults and competitor charts retain their existing
validated results.

## Exact R1024 / W2 arithmetic

The reference is the independently archived original generated norm expression,
with source SHA-256
`c4cb1809c630480191249aa7f830807153be72a3fc645843c0eef73c6603722f`.
Its launch is XBLOCK1, R0_BLOCK1024, two warps, one stage and FP fusion enabled.
PTX/TTGIR tracing identifies layout `[1,8] / [1,32] / [1,2]`, one row per CTA,
and two source-loop segments across width2048.

Each thread has 16 accumulator slots. For corresponding raw FP32 residuals
from the two segments, each slot uses:

```text
a[i] = fma_rn(raw_second[i], raw_second[i], mul_rn(raw_first[i], raw_first[i]))
p    = (((a[0] + a[1]) + a[2]) + ... + a[15])  # FP32 add_rn at each step
```

Warp reduction offsets are 16/8/4/2/1, followed by a shared-memory offset-1
combine of two warp partials. The authored Gluon helper pins this arithmetic.
Statistics use the unrounded FP32 residual; stored H and normalized activations
retain their FP16 rounding boundaries. Row quantization preserves CK0.2.34's
FP16 denominator/division rounding and FP32 scales. QKV uses the existing
INT8 GEMM.

Two real contiguous FP16 B4 captures `[4,1797,2048]`, plus M1/17/129 row
slices, pass against that independent expression and public CK APIs. Debug
checks cover H, FP16 norm, Q, FP32 scale and QKV; non-debug checks cover H,
Q, scale and QKV, since norm is not materialized. Inputs and weights remain
unchanged. This establishes the fixed W2 contract on tested data, not
equivalence with arbitrary old natural schedules.

The initial attempt failed before numerical comparison because a JIT function
used Python string `join` to build inline-assembly constraints. One documented
syntax repair substitutes an equivalent constant string. The arithmetic,
launch and acceptance thresholds remain unchanged; the failed attempt and
repair are retained separately.

## Local performance screen

| Local chain | Original W2 + public quantization | Fused W2 |
| --- | ---: | ---: |
| CUDA event | 0.604329 ms | 0.561580 ms |
| Synchronized host wall | 0.626057 ms | 0.583725 ms |
| Registers | 56 | 70 non-debug / 71 debug |
| Shared bytes / spills | 8 / 0 | 8 / 0 |

Each call includes the same H ownership clone, allocations, residual/norm,
quantization and QKV GEMM. Three warmups per variant precede six alternating
ABBA/BAAB blocks, ten calls per sample. Mean event saving is **0.042749 ms
(7.07%)**, with **six of six** blocks faster, passing the ≥0.02 ms and
≥five-winning-block screen.

Order-stratified samples differ: ABBA blocks save 0.060495 ms on
average, BAAB blocks 0.025002 ms. Both order groups improve, but this asymmetry
prevents treating the mean as a precise prediction of complete-decoder gains.
Register/shared-memory counts do not establish occupancy or a stall cause.

## Ordinary module integration: full-video screen rejected

The private module uses an opaque custom op and carries the preceding FFN
residual between blocks. It separates norm's two-warps launch from FFN's
eight-warps setting and reuses all 144 existing INT8 modules. Device,
Triton/CK version and shape guards are explicit. The baseline and candidate
run in separate processes with ordinary
`torch.compile(mode="max-autotune-no-cudagraphs", dynamic=False)`.
Neither natural worker patches Autotuner/CK, binds reductions, observes the
hot path or resets Dynamo.

A separate diagnostic worker checks the actual candidate against an
independent W2 norm/public-CK oracle: **35/35 target layers are exact** at
all materialized boundaries. Its wrappers do not enter either natural worker.

The complete first video has **124 frames at 768×1344**, with no resize,
crop or frame drop. One FP16 encode supplies the identical saved latent to
both decoders. Its channels-last stride, tensor SHA and immutability are
checked; source uint8 RGB reconstructs the reader's FP32 reference exactly.

The primary screen fails mean/global PSNR; the strict screen also fails.
Source-quality delta checks pass: candidate mean-frame PSNR changes by
**+0.000784 dB**, the worst per-frame change is **−0.013189 dB**, and there
are **zero additional frames below 30 dB**. Their limits remain −0.01 dB
mean, −0.05 dB per frame and zero additional below-threshold frames.

These results do not establish perceptual visibility or attribute all RGB
differences to the W2 producer. Independent compilation can also change the
untouched reductions. A post-run, read-only audit associates source files with
their selected `.best_config` using the installed Torch2.11 cache-key formula:

| Traced operation | Baseline selected launch | Candidate launch |
| --- | --- | --- |
| Target norm1 `_8`, 35 baseline callsites | X1 / R2048 / W16 / stage1 | Fixed X1 / R1024 / W2 / stage1 |
| Untouched norm `_4`, identical source SHA | X2 / R2048 / W16 / stage1 | X1 / R2048 / W16 / stage1 |

This confirms two schedule changes and prevents attributing the complete RGB
difference solely to the W2 producer. It does not identify all decoder norms.
Selected compiler resources remain unknown because the config records do not
link a specific Triton artifact; compiled tuning candidates are not promoted
to selected-resource measurements.

Tiny source-PSNR changes do not override the failed
comparison screen. The retained raw status is `rejected_quality`, with
`timing_status=not_run`; its `adoption_status=not_decided` is preserved, while
the review decision for this round is **not adopted**.

The eight-video suite, ComfyUI offload/reload validation and paired full-stage
timing do not run after this failure. No threshold is lowered and no new
complete-decoder speedup is claimed.
