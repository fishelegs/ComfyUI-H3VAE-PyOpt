# CI and Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a lightweight pull-request CI gate that validates syntax, critical lint errors, and CPU-only regression tests without model downloads or GPU access.

**Architecture:** Use one GitHub Actions workflow with a Python 3.11/3.12 matrix. Install CPU-only PyTorch plus pytest and ruff; do not install Triton, safetensors, model code, model weights, TensorRT, or comfy-kitchen because current CPU tests do not need them. Keep GPU/model validation documented as a separate manual path.

**Tech Stack:** GitHub Actions, Python, pytest, ruff, CPU PyTorch.

**Spec:** `docs/superpowers/specs/2026-09-18-codex-oss-readiness-design.md`

## Global Constraints

- Work only on `codex-oss-readiness`.
- CI must not download MiniMax H3 model code or model weights.
- CI must not require a CUDA runner.
- CI must not install optional TensorRT or comfy-kitchen dependencies.
- Test Python 3.11 and 3.12.
- Preserve the existing GPU benchmark scripts unchanged in this phase.

**Interfaces:**
- Consumes: `tests/test_benchmark_cpu.py`, `tests/test_runtime_tiling.py`, and `tests/test_version_metadata.py`.
- Produces: a `CPU tests` status for pushes to `main` and pull requests.

- [ ] Configure triggers for pull requests and pushes to `main`.
- [ ] Set workflow permissions to `contents: read`.
- [ ] Use a Python matrix of `3.11` and `3.12`.
- [ ] Install CPU-only `torch>=2.8` from the PyTorch CPU index.
